# ADR 0016 — Contrôles automatisés et chargement des pages

Décision du 11 novembre 2026 : ajouter un workflow GitHub Actions sur `main`, les PR et le lancement manuel. Les actions sont épinglées à des commits officiels ; les permissions restent en lecture et aucun déploiement n’est ajouté. Le workflow installe les dépendances du lockfile, exécute typage, lint, domaine, build, budgets et parcours Chromium, puis conserve uniquement rapports et captures de test pendant sept jours. Le bundle de production n’est pas joint aux artefacts.

`npm run test:interactive:all` démarre les serveurs temporaires, sérialise les scénarios possédant le même port et reconstruit la référence A4 depuis `0addb36d662842040cc8ed64e8b2c0ca81eac810`. Seul le code est archivé, sans fichier d’environnement ; les ressources publiques sont partagées. Les serveurs et dossiers temporaires sont fermés en fin de contrôle. Les tests de domaine restent séparés de ce lancement navigateur. Une reprise locale par `INTERACTIVE_TEST_START_AT` est possible ; son rapport indique explicitement qu’elle ne représente pas une exécution complète.

L’audit utilise `@axe-core/playwright` 4.14.0 et les règles WCAG 2 A/AA, 2.1 A/AA et 2.2 AA. Vingt-six vues sont contrôlées, sur mobile et desktop : préparation, mascottes, réflexion, pause, correction, comptage, confirmation, bilan, Solo, cartes, diagnostic et zoom. Les règles restant à vérifier manuellement sont conservées dans [accessibility-results.json](accessibility-results.json). Zéro violation détectée automatiquement ne remplace pas un essai avec lecteur d’écran, zoom ou ENI.

Les changements d’accessibilité comprennent le groupe de réponses nommé, le nom de la fenêtre d’image et le retour du focus après fermeture des fenêtres de comptage, navigation et confirmation. Le nettoyage ferme le dialogue natif avant de restituer le focus, y compris pendant la vérification de montage de React. Les compteurs de réflexion et de battement n’annoncent plus chaque seconde ; la fin de réflexion dispose d’une annonce distincte.

L’accueil charge désormais le générateur et la bibliothèque à la demande. Le routeur interactif initialise seulement les préférences et les styles ; diagnostic, cartes et jeu sont des entrées distinctes. Les banques du jeu ne sont plus téléchargées par l’accueil, les cartes ou le diagnostic. [performance-results.json](performance-results.json) mesure les dépendances statiques du manifeste, JavaScript et CSS gzip, sans polices ni médias. [performance-browser-results.json](performance-browser-results.json) vérifie les requêtes réelles du build et le premier affichage de question avec médias déjà contrôlés.

Budgets retenus pour cet incrément : accueil ≤ 150 Kio gzip ; cartes et diagnostic ≤ 200 Kio ; jeu complet ≤ 3 Mio. **Le plafond provisoire du jeu dépasse la proposition V4 de 200 Ko** : ses banques et une partie du code partagé représentent encore l’essentiel des quelque 2,4 Mo gzip. Le découpage par domaine, le travail hors du fil principal et les mesures sur ENI restent ouverts. Les nouveaux budgets empêchent une régression du chargement léger sans annoncer ce chantier terminé.

`npm run check:interactive:secrets` télécharge Gitleaks 8.30.1 depuis sa distribution officielle, vérifie une empreinte SHA-256 épinglée et teste sa détection et le masquage avec un jeton synthétique non émis, gardé dans un dossier temporaire. Le contrôle couvre les commits depuis C0 et les fichiers modifiés / non suivis actuels. Il ne reproduit jamais le contenu des correspondances dans la console ou le rapport versionné. Ce contrôle des changements **ne clôt pas S1 ni F22** : authentification historique, rotation, historique antérieur et audit du bundle complet restent à traiter. Voir [audit sécurité](audit-securite.md).

La validation locale et les résultats du service GitHub sont distincts. Le workflow et ses commandes sont vérifiés localement ; l’état d’une exécution hébergée n’est pas attesté sans accès au service. Les domaines bloqués de l’environnement et sa configuration publiée ne sont pas modifiés.
